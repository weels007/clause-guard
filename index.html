how it works

Four steps, one auditable trail

The model proposes. Deterministic code decides. Validators check independently.

  1. 01

    Policy registered

    The owner records a rules URL and analyst guidance. Once a policy has produced an assessment it is locked, so it can never be re-pointed underneath old verdicts.

  2. 02

    Rules fetched

    Inside the non-deterministic block the contract renders the page as text. The excerpt is digested, so an auditor can tell which text produced the verdict.

  3. 03

    Committee decides

    The model returns a verdict, a risk level and a verbatim citation. A citation that is not in the page cannot certify anything — the verdict drops to REVIEW.

  4. 04

    Stored on consensus

    Validators re-run the fetch and the judgement, then compare verdict and risk level. Disagreement writes nothing at all.

why it holds

Built so the failure modes are boring

Grounded citations

Quotes are folded to letters and digits and matched against the fetched page, so formatting cannot fake or break evidence.

No double submit

Every assessment carries a caller-scoped submit_ref. A replay is refused instead of minting a second record.

Funder-only custody

Only the depositor can release or refund, and a refused deposit becomes a refundable orphan rather than a stranded one.

Bounded work

Capped policies, capped assessments, capped strings, and a summary that reads counters instead of walking the whole set.

        How ClauseGuard decides

        What the committee compares

        Two fields only: the verdict (COMPLIANT / NON_COMPLIANT / REVIEW) and the risk level (LOW / MEDIUM / HIGH). An integer score is exactly the value two independent models disagree on — and when validators disagree the transaction becomes undetermined and writes nothing.

        The stored number is a fixed representative of the agreed level: LOW 20, MEDIUM 50, HIGH 80. It cannot drift between runs.

        When the citation is not there

        The model must quote a sentence from the fetched page. The quote is folded to letters and digits and must appear in the page text. If it does not, the verdict is downgraded to REVIEW and the quote is dropped — the assessment still completes, because a hard failure would leave consensus with nothing to agree on.

        Error taxonomy

        [EXPECTED]
        bad input, wrong caller, duplicate reference. Deterministic: both nodes must match.
        [EXTERNAL]
        the rules page is empty or gone. Deterministic, recorded instead of retried.
        [TRANSIENT]
        network or 5xx. Both nodes transient means agreement, so it retries.
        [LLM_ERROR]
        malformed model output. Always disagrees, forcing a rotation to a new leader.

        Money rules

        • An escrow needs a COMPLIANT assessment the funder ran themselves — one verdict backs one escrow.
        • Only the stored funder can release or refund. The payee has no pull path.
        • A refused deposit becomes an ORPHAN owned by the sender, refundable, instead of being stranded by a revert.
        • After 30 days anyone may trigger the refund — but it always pays the funder.
